# Report contribution: inter-agent communication (Anupama)

SilverFile's agents communicate through shared, typed LangGraph state rather than independent free-text protocols. I retained the existing Pydantic contracts for Intake answers, document records, cited rule decisions, monetary line values, revision requests and escalation tickets. Agent-boundary validation rejects malformed work products, mismatched identities, invalid routing names and writes outside an agent's responsibility. Extraction owns transcription; Rules owns meaning; Computation owns derived lines through the existing tool boundary; Review returns revisions without repairing values itself.

The W-2 extractor sends local image bytes to Claude vision and validates its observations with the existing W2Record. It requires an observation for each supported field, permits explicit blanks where the shared record allows them, and escalates unreadable, missing, invalid or incomplete responses instead of publishing a guessed record. It retains the image path, content hash and model-response identity. Manual 1099-INT, 1099-DIV, 1099-R and SSA-1099 entries use the existing discriminated union and retain direct-input provenance, who entered them and when.

A line's audit chain now retains its document box, original input provenance and calculation arguments/results through dependent lines and revisions. Named Intake fields and document-specific extraction revisions extend the existing routing interfaces. Evidence changes archive prior work, invalidate stale lines and rule decisions, and require fresh issue identities instead of reusing earlier human approvals. Inventory replacement/retraction uses coordinated reducer replacement; competing extraction writes still use the existing staff-selection workflow.

The HTML draft view makes each available amount a keyboard/click disclosure with a hover source summary. Source identity/time and calculation inputs are readable before the complete audit details. Semantic table headers, large text, visible focus and responsive wrapping aid review. The view withholds monetary results when evidence is stale/unreviewed, documents are absent/unverified, or calculations/dependencies remain stubs. It is the supported-line preparation view; it does not file a return or supply advice.

The unchanged baseline was 137 passing tests, verified locally before edits. Communication tests use both committed W-2 image files with provider doubles and exercise all four manual forms, malformed messages, role violations, strict serialization, correction/re-extraction paths, evidence changes and SQLite restart preservation. The full suite reached 190 passing tests; focused communication tests number 53. Local browser checks cover Enter, Space and mouse activation, source hover text, visible provenance and a 390px layout. No Anthropic credentials were configured, so no live vision accuracy is claimed. MCP tax math, policy content, full dashboard, live evaluation, screen-reader review and final team demo remain owner/team dependencies. Detailed commands and interfaces are in ANUPAMA_HANDOFF.md.
